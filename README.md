# PPM - Python Project Manager

**ppm** or **Python Project Manager** is a tool written in [Python](https://python.org)

ppm handles your projects easily, initiliaze a project, code, test...

## Basic ppm usage

Using ppm CLI is very easy. To get its help, run: `ppm help` or `ppm h` to get its help screen:

```
ppm - Python Project Manager.
Version: v1.0.0

Commands are:

new/n :: Create a directory and initialize it
init :: Initialize a project
deinit/di :: Deinitialize a project
clone/cl :: Clone a git repo (no system git required) and set up its dependencies

check/c :: Check project using ruff.
clear-rc/crc :: Clear cache generated by ruff
run/r :: Run the project with the local venv python.
run-script/rs :: Run a named command from ppm.toml's [scripts] table
globalrun/gr :: Use the system-global python to run the code.
cart/ct :: Cart a dependency to project
decart/dct :: Decart a dependency from project
rm-venv/rvenv :: Remove virtual environment (NOT RECOMMENDED)
build-venv/bvenv :: Build virtual environment
order/o :: Order (or install) all carted packages.
install/i :: Install a dependency to project (supports --dry-run)
uninstall/u :: Uninstall a dependency from project (supports --dry-run)
update/up :: Update installed dependencies, all or specific (supports --dry-run)
list/l :: List installed and carted dependencies
status/s :: Show project overview (venv, main file, dependency counts)
doctor/doc :: Run a full consistency check across venv, toml, and lockfile (supports --fix)
scan-tree/st :: Recursively print a tree of all Python files in a directory
help/h :: Print help and exit
version/v :: Print version and exit
```

**ppm** auto-adds a `BATCH/SHELL` Script to the project directory (but placed in .gitignore), So you dont need to add ppm to your PATH.


Now you may have noticed cart and order. What are those?

## Carting and ordering

`Carting` is a mechanism that adds the dependency to your ```ppm.lock``` file but doesn't install it. If you cart a pinned version (e.g. `ppm cart "requests==2.31.0"`), that pin is preserved and used later by `order`.

`Decarting` is a mechanism that removes the dependency from your ```ppm.lock``` file.

`Ordering` is installing, but for `Carted` dependencies only.

## Cloning a repo

`ppm clone <repo>` (or `ppm cl`) clones a remote git repository **without requiring a system git installation**.

```sh
ppm clone alanbutidk/ppm          # short GitHub form
ppm clone https://github.com/user/repo mydir
ppm clone user/repo --branch dev
```

If the cloned repo has a `ppm.toml`, ppm automatically builds a venv for it; if it also has a `ppm.lock`, every locked (non-carted) package gets installed right away; so `ppm clone <repo> && cd <repo> && ppm run` can take you from nothing to a running project in one line, with no git or manual pip step required.

## Scripts

`ppm.toml` can define a `[scripts]` table, similar to npm's `scripts`:

```toml
[scripts]
test = "python -m pytest"
lint = "ppm check main.py"
hello = "echo hello from ppm"
```

Run one with `ppm run-script <name>` (or `ppm rs <name>`). The script runs through a shell with the project's venv `bin`/`Scripts` directory prepended to `PATH`, so a bare `python` inside a script resolves to the venv's interpreter.

## Keeping dependencies up to date

`ppm update` (or `ppm up`) reinstalls packages with `--upgrade` and refreshes their lockfile entries.

```sh
ppm update              # updates every installed (non-carted) package
ppm update requests     # updates just requests
ppm update --dry-run    # shows what would be updated, changes nothing
```

`install`, `uninstall`, and `update` all support `--dry-run` to preview changes without touching the venv or the lockfile.

## Checking project health

`ppm status` (or `ppm s`) gives a quick overview: project name/version, main file, venv presence, and dependency counts.

`ppm doctor` (or `ppm doc`) goes further; it checks `ppm.toml`, the venv, `.ppm_paths`, and cross-references `ppm.lock` against what's actually installed to catch drift. Add `--fix` and it auto-repairs what it can: recreating a missing main file, rebuilding a missing/corrupt venv, and reinstalling any package that drifted out of the venv.

```sh
ppm doctor
ppm doctor --fix
```

## Scanning for Python files

`ppm scan-tree` (or `ppm st`) recursively scans a directory and prints a tree of every `.py` file it finds, skipping `.venv`, `__pycache__`, `.git`, and similar noise directories.

```sh
ppm scan-tree                 # scan the current directory
ppm scan-tree ./src           # scan a specific directory
ppm scan-tree --all           # include venv/cache/git directories too
```

## Make my project

First, run `ppm new` or `ppm init` (init if your inside the directory that needs to have the project)
Then do the setup tasks it asks you; or pass `--yes` (`-y`) to skip the prompts and use sensible defaults, which is handy for scripts/CI.

A main file (e.g. `main.py`) is scaffolded automatically if it doesn't already exist, so the project is runnable right away.

Now if your project has a dependency that is not BUILT-IN, you need to run:

`ppm install [Your-Dependency-Name]` or `ppm cart [Your-Dependency-Name]`

> If you have carted the dependency: run: `ppm order`


And to test after coding, run: ```ppm run```
